# 2026 混音與交付實作

> 可交付的混音不只要好聽，還要確認訊號來源、時間範圍、格式與實際輸出的檔案。

本頁依 Avid 2026.4 文件整理。一般 Bounce 的概念可接回 2023.3 的 [[PT-Ch50a-混音Track與訊號流]]；MPEG-H 與新版 Immersive Panner 有額外版本、方案與安裝條件，不能直接套用到舊版或 Dolby Atmos。

## 1｜輸出一份可驗證的立體聲混音

**Bounce Mix** 把指定 output 或 bus path 聽得到的訊號寫成新檔案。它不會自動包含 Session 中每條 Track：Mute、Solo、路由和選取範圍都會影響結果。選取若在殘響結束前停止，輸出也會在那裡結束。

1. 播放整首並確認要交付的 Tracks 路由到預定的 Mix Source；檢查沒有意外的 Solo 或 Mute。退出相關 Track 的 Record Enable 與 Input Only monitoring。
2. 在 Timeline 選取從開始到殘響完全衰減之後的範圍。選 **File > Bounce Mix**；預設 Mac 快捷鍵為 **Command+Option+B**，Windows 為 **Control+Alt+B**。
3. 設定正確的 Mix Source、目的地、檔名及委託方要求的格式、sample rate 和 bit depth，再按 **Bounce**。
4. 用獨立播放器或匯回 Session 檢聽成品開頭、結尾和重點段落；核對檔案長度、聲道與規格，並確認檔案確實存在於目的地。

| 選擇 | 何時有用 | 要檢查什麼 |
|---|---|---|
| Offline Bounce | 不需即時聆聽，想加速產檔 | 成品仍須事後完整抽聽與檢查 |
| Real-time Bounce | 需要在 Bounce 過程中聆聽 | 文件指出 Bounce 時不能手動改控制；若需現場調整，可考慮錄製到 Track |
| Bus recording | 希望在 Session 中錄下 submix，或錄製時調整控制 | 需要可用的 Track、voice、bus，並避免重複監聽 |

> [!warning] 聽得到不代表會輸出
> 官方文件指出 Record-enabled 或 Input Only monitoring 的 Tracks 不包含在 Bounce 中；Solo 也會限制輸出內容。不要只看輸出檔存在，務必回聽。

> [!tip] 實務連結
> 先把委託方要求寫成格式、聲道、長度與檔名清單，交付前逐項對照。來源：[Reference Guide 2026.4，PDF 1714、1716–1717](https://resources.avid.com/SupportFiles/PT/Pro_Tools_Reference_Guide_2026.4.pdf#page=1714)；[Shortcuts Guide 2026.4，PDF 52](https://resources.avid.com/SupportFiles/PT/Pro_Tools_Shortcuts_2026.4.pdf#page=52)。

## 2｜需要 16-bit 時，在正確位置使用 Dither

降低 bit depth 是把較細的數值表示壓到較少的階層；Dither 以受控的低電平雜訊減輕量化失真。2026.4 Reference Guide 建議輸出至 16-bit 時使用 Dither，並指出 Bounce 降低位深時不會自動加入 Dither。

1. 確認交付確實要求 16-bit，且識別 Bounce 的 Mix Source path。
2. 建立或使用指派到該 path 的 Master Fader，在訊號鏈最後插入 Dither plugin，設定目標 bit resolution 與適合的 noise shaping。
3. Bounce 時選擇 16-bit；回聽安靜段落，並檢查交付檔的位深。

> [!warning] 位置與時機
> Dither 應放在該 Mix Source 的 Master Fader 最後處理位置；Master Fader inserts 為 post-fader。一般錄音與播放時依文件建議 bypass；不要把 16-bit 的設定無條件套到其他交付。若同時改 sample rate 與降低位深，文件建議先以較高位深完成 sample rate conversion，再進行加 Dither 的位深降低。

> [!tip] 實務連結
> 一個專案可能同時有高解析母帶及 16-bit 版本；每個輸出要依規格檢查訊號鏈，避免為了其中一份成品而誤處理其他版本。詳見 [[PT-Ch50d-DelayCompensation與Dither]] 與 [Reference Guide 2026.4，PDF 1714–1715](https://resources.avid.com/SupportFiles/PT/Pro_Tools_Reference_Guide_2026.4.pdf#page=1714)。

## 3｜建立 MPEG-H Scene 與 Object

當交付規格要求 **MPEG-H**，Renderer 能把場景中的 Bed 和 Object 組織成可支援不同呈現方式的內容，例如讓聽眾調整對白。Bed 承載聲道佈局；Object 則帶有可控制的空間資訊。先確定收件方要求，再決定是否需要這條流程。

1. 確認使用 **Pro Tools Studio 或 Ultimate**、Session 為 **48 kHz**，並從 Avid Link 或 MyAvid 安裝 MPEG-H Renderer。
2. 選 **Setup > I/O > Renderer**，在 Renderer selector 選 **MPEG-H** 並按 OK。首次啟用時依監聽與製作需求指定 Reference Layout。
3. 需要典型的單 Bed、多語言起點時，可使用 Renderer 的 **Setup Assistant**；它會依所選項目建立 Tracks、assignments 與 scene。重新執行前須移除現有 Object／Bed assignments。
4. 要手動建立 Object，在 Track Output selector 選 **MPEG-H Renderer > Assign as Object**；要建立 Bed，可在 Output 或 Send 選 **MPEG-H Renderer > Create New Bed**，再選 channel width。
5. 檢查 Renderer 的 scene 與 Track assignments，播放各個元素並核對監聽。若使用 Setup Assistant，也要逐一確認它產生的路由與 presets 是否符合需求。

> [!warning] 別把 Renderer 當成通用格式轉換器
> MPEG-H Renderer 僅支援 48 kHz Session；檔案格式、監聽佈局與互動設定要依交付要求確認。MPEG-H、Dolby Atmos 是不同交付路線；不能因為兩者都有 Object 就假設設定或輸出可互換。Atmos 的概念參見 [[PT-Ch58a-DolbyAtmos架構與Renderer連接]]。

> [!tip] 實務連結
> 多語言節目可先確認哪些元素由製作端固定、哪些由聽眾調整，再設計 scene；不要等到最後輸出才發現交付要求。來源：[What's New 2026.4，PDF 22–27](https://resources.avid.com/SupportFiles/PT/Whats_New_in_Pro_Tools_2026.4.pdf#page=22)；Renderer 詳細控制參見 [Fraunhofer 文件](https://mpegh.com/protoolsManual/)。

## 4｜定位 Object 並建立交付佇列

2026.4 的 **Pro Tools Immersive Panner** 供 MPEG-H 或 Audio Vivid Renderer 的 Object 使用。多聲道來源可藉 anchor point 與各聲道參數共同決定位置；單聲道來源的控制較少，anchor 隱藏。它不能用於 Dolby Atmos Renderers 或 Pro Tools mixer，故先確認正在使用的 Renderer。

1. 將目標 Track 指派為 MPEG-H Object，開啟其 Immersive Panner，播放素材並調整位置；多聲道素材同時觀察各來源聲道的位置。
2. 檢查移動是否符合畫面與監聽佈局，並核對對白等關鍵內容仍清晰。
3. 選取要交付的 Timeline 範圍，選 **File > Bounce Mix**，將 Export Type 設為 **MPEG-H**，填寫檔名與目的地後按 **Bounce**。
4. 在 MPEG-H Renderer 的 Export 頁確認 scene 有效、佇列正確，依交付規格選格式、frame rate、sample format 與 channels；按 **Add to Queue**，再按 **Start Export**。
5. 輸出完成後確認檔案、格式與內容；對方若要求特定驗證工具或播放環境，以其交付規範做最終驗證。

| 交付前核對 | 為什麼 |
|---|---|
| Scene 有效、Object／Bed 指派正確 | 時間軸有素材並不保證 scene 結構符合目的 |
| 佇列格式與目的地正確 | 可加入多種格式，各自有檔案位置 |
| 長度包含尾音 | Timeline selection 決定輸出範圍 |
| 播放與驗證結果符合收件方規格 | 輸出完成不等於收件系統已接受 |

> [!warning] Online Bounce 的聆聽限制
> MPEG-H 文件註明取消 Offline 時，online bounce 是靜音的；不要據此誤判一定沒有產出，也不要把它當成正常的即時聆聽驗證。Immersive Panner 在 2026.4 文件列為 Studio／Ultimate，且僅供 AAX Renderer plugins 使用。

> [!tip] 實務連結
> 空間交付應連同 scene、格式與監聽假設一起交接；一般 stereo Bounce 與 MPEG-H export 使用不同的驗證條件。來源：[What's New 2026.4，PDF 29–31](https://resources.avid.com/SupportFiles/PT/Whats_New_in_Pro_Tools_2026.4.pdf#page=29)。

> [!abstract] Takeaway
> 先確認路由和範圍，再依交付規格決定位深與格式；MPEG-H 要額外驗證 Renderer、scene、佇列與收件端的播放要求。
